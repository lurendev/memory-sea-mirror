# 记忆海-镜子 · 模板

把「记忆海-镜子」变成你自己的版本：一个单文件页面 + 零依赖 Node 服务，用来把想法、人物、事件、知识做成可旋转、可点击的 3D 星云图。

当前为**空白模板**：启动后只有「观测点」和 8 个分层（日记、日常活动、身体状态、情绪暗流、人际互动、认知沉淀、未来锚点、梦境），其中「梦境」默认带一个「梦」节点，内容由你自己录、导入或在日记抽屉里写。

## 项目架构

整体是「单文件前端 + 零依赖 Node 服务 + 文件存储」，没有数据库、没有构建步骤：

```text
浏览器（index.html）
├─ 配置层    TEMPLATE：标题、分层、演示数据、突触修剪参数、本地存储键
├─ 渲染层    Canvas 2D 手写 3D 投影；8 种视图与出生/旋转/斥力动效
├─ 交互层    选中、检索、分层过滤、新增节点/分层、手动关联、视角控制
├─ 数据层    nodes / edges / layers 常驻内存；localStorage 缓存 + PUT /api/graph 同步
└─ 日记抽屉  文本 → POST /api/ai-parse → 返回实体与关系 → 写入图谱

Node 服务（server.js）
├─ 静态服务  下发 index.html；拦截 data/ 与隐藏文件
├─ 访问门禁  Basic Auth（SITE_PASS）+ 30 分钟无操作自动退出
├─ REST API  GET/PUT/DELETE /api/graph、POST /api/ai-parse、
│            POST /api/save-diary-txt、GET /health
├─ 文件存储  data/graph.json、*.bak（上一版）、diary_log.md（日记原文）
└─ 模型代理  服务端调用 DeepSeek，LLM_API_KEY 不下发到前端

部署链路：本地 docker build → 推送阿里云 ACR → Sealos 拉镜像运行
          （单实例 + PVC 挂载 /app/data）
```

数据流：页面改动先写入浏览器本地缓存，再 `PUT /api/graph` 覆盖服务器快照；服务端保存前把旧文件复制为 `.bak`。日记抽屉额外把原文追加到 `data/diary_log.md`。

## 功能

- **3D 星云图谱**：8 种视图（星云、小银河、聚类、列表、矩阵、旭日、思维导图、阅读），支持旋转、缩放、平移、选中居中。
- **分层管理**：8 个默认分层（含梦境），可新增自定义分层、单独显示/隐藏、按标题/描述检索过滤。
- **节点编辑**：新增节点、手动建立关联、编辑描述与权重；分层与节点都随快照保存。
- **AI 日记裂变**：一篇日记自动拆成 2–4 个实体，按语义落到对应分层，并用「包含 / 导致 / 引发」等关系连回日记主节点。
- **突触修剪**：长期未打开的节点逐渐变暗、到期限后隐藏，点开即恢复，模拟记忆遗忘。
- **数据导入导出**：JSON 快照导入/导出，Markdown 导出；服务端支持 `PUT` 直接写入整份图谱。
- **私密与门禁**：Basic Auth 访问密码、无操作自动退出、`data/` 与隐藏文件不可通过 URL 下载。
- **持久化部署**：Sealos + PVC，重启/重新部署不丢数据；单实例写入，避免多副本冲突。

## 快速开始

```bash
npm start                 # 等同 node server.js
# 打开 http://localhost:8787
```

自定义端口：

```bash
# Windows PowerShell
$env:PORT=9000; node server.js
# macOS / Linux
PORT=9000 node server.js
```

启用 AI 日记裂变（Node >= 18）：

1. 打开项目根目录的 `.env`，填写 `LLM_API_KEY=你的Key`（可同时改 `LLM_API_URL`、`LLM_MODEL`）。
2. 重启服务：`npm start`。

`.env` 只被服务端读取，已加入 `.gitignore`，不会提交到 Git，也不会出现在前端。

也可以临时用环境变量覆盖（环境变量优先）：

```bash
# Windows PowerShell
$env:LLM_API_KEY='你的 Key'; npm start
# macOS / Linux
LLM_API_KEY=你的Key npm start
```

可选配置：`LLM_API_URL`（默认 DeepSeek `https://api.deepseek.com/chat/completions`）、`LLM_MODEL`（默认 `deepseek-chat`）、`LLM_TIMEOUT_MS`（默认 60000）。

## 隐私与访问门禁

站点包含私密日记，部署到公网前必须先设置访问密码：

```bash
# .env 或部署平台环境变量
SITE_USER=你的用户名      # 可选，默认 admin
SITE_PASS=你的强密码      # 必填；不设置则门禁关闭（启动时打印警告）
```

- 设置 `SITE_PASS` 后，访问 `/` 页面或任意 `/api/*` 接口都会先返回 `401` 并带 `WWW-Authenticate`，浏览器弹出登录框；密码由浏览器缓存，刷新无需重复输入。
- 未设置 `SITE_PASS` 时服务照常启动，但访问门禁关闭，仅适合本机调试。
- `data/` 目录下的任何文件（`graph.json`、`diary_log.md` 等）都不能通过 URL 直接下载，静态服务会拒绝；数据只通过 `GET /api/graph` 在内存中读取返回。
- 隐藏文件（如 `.env`）也不会被静态服务下发。
- 登录失败限流：同一 IP 15 分钟内密码错误 5 次即锁定 15 分钟，锁定期间即使密码正确也返回 `429`，防止无限爆破。
- 前端 30 分钟无鼠标/键盘操作后自动退出：发送一次错误凭证请求清掉浏览器的 Basic Auth 缓存并刷新，重新要求输入密码。
- 公网 HTTPS 由部署平台（如 Sealos）自动提供，代码侧无需处理。

## 改成你自己的站点

所有可配置项集中在 `index.html` 顶部的 `TEMPLATE` 对象（约第 441 行）：

| 字段 | 说明 |
| --- | --- |
| `title` / `subtitle` / `version` | 页面标题、页头名称、版本号 |
| `hubTitle` / `hubDesc` | 中心节点（观测点）的名称与说明 |
| `layers` | 分层列表：`id`（内部标识，保存过数据后不要改）、`label`（显示名）、`color`（颜色）、`desc`（选中该层时显示的介绍） |
| `demo` | `true` 生成少量示例节点；`false` 启动为空分层（模板默认） |
| `forgetStartDays` / `forgetHideDays` | 突触修剪：多少天未打开开始变暗、多少天后完全隐藏（默认 30 / 90） |
| `source` | 页头「来源 xxx」，留空则不显示 |
| `exportName` | 导出 Markdown / JSON 的文件名前缀 |
| `storageKey` / `presetKey` / `tokenKey` | 浏览器本地存储键；同一域名部署多份时必须改成不同前缀 |

### 新增内容

页面上可以直接操作：

1. **新增节点**：点「＋ 新增节点」，填标题、分层、描述、权重即可。
2. **新增分层**：点「＋ 新增分层」，输入名称后建立一个自定义分层；分层会写入快照，保存过数据后 `id` 不要随意更改。

也可以改代码：在 `index.html` 的 `if (TEMPLATE.demo) { ... }` 分支里按下面的结构加：

```js
layer('knowledge', [
  // [标题, 描述, 权重(0.3–1), 附加字段(可选)]
  ['复利', '收益随时间的自我强化。', 0.8],
  ['沉没成本', '已经付出、无法收回的成本。', 0.6, { flag: '待补' }]
]);
```

### 导入现成资料

左侧「数据」区可以导入 JSON（按快照恢复节点、连线与分层信息），也可以导出 JSON / Markdown；暂不支持导入 Word 或 Markdown。服务端可以用 `/api/graph` 直接 PUT 一份 JSON（见下文）。

手动连线：选中一个节点 → 「＋ 关联节点」→ 点另一个节点，可建立 `relates` 关系，用虚线显示。

## 日记裂变（AI）

点击页面右下角的 📝，写下日记后点「发射进入星云」。前端会把文本发给 `POST /api/ai-parse`，由服务端调用大模型拆成 2–4 个实体和关系：

1. 新建一个「日记」层主节点（`diary_时间戳`），保存日记全文。
2. 同名实体自动复用；新实体按 AI 判断落到「日常活动 / 身体状态 / 情绪暗流 / 人际互动 / 认知沉淀 / 未来锚点」之一。
3. 日记主节点用「包含」连线指向各实体，实体之间使用 AI 识别的关系词（如「导致」「引发」）。
4. 新节点从主节点位置出生，1 秒内放大，并借助力导向斥力向外散开。
5. 结果立即保存到本机和服务器。

未配置 `LLM_API_KEY` 时接口会返回明确错误，页面会提示，不会静默失败。

### 旧数据兼容

如果你之前保存过旧分层的图（`core`、`events`、`note` 等），旧节点不会出现在新分层里，左侧过滤也会异常。测试新结构前请先备份并清空 `data/graph.json`，或先备份再用页面上的清空功能重新开始：

```powershell
Copy-Item data\graph.json data\graph.old-layers.json
Remove-Item data\graph.json
```

浏览器本地也有缓存，必要时在页面里清空本地数据后再刷新。

## 突触修剪（遗忘）

节点会记录最后一次被点开的时间（`la`）。超过 `forgetStartDays`（默认 30 天）未打开后，节点逐渐变暗、连线变细；到 `forgetHideDays`（默认 90 天）完全隐藏。观测点和分层不参与修剪。

隐藏后仍可通过检索、列表、阅读视图找到，点开一次即恢复亮度并重置计时。左侧「显示 → 突触修剪」可整体关闭该机制。

## 数据与接口

- 服务端数据：`data/graph.json`；`data/` 已在 `.gitignore` 中，不会被提交到 Git
- 每次保存前把上一版复制到 `*.bak`（只保留最近一份，没有历史快照目录）
- `GET /api/graph` 读取；`PUT` 保存；`DELETE` 清空（仅 API，页面不再提供入口）
- `PUT` 要求 `nodes` / `edges` 为数组、必须包含 `hub` 节点、节点不超过 5000，连线不能自环或指向不存在的节点
- `POST /api/ai-parse` 接收 `{ text }`，返回 `{ nodes, links }`；需要 `LLM_API_KEY`
- `POST /api/save-diary-txt` 接收 `{ date, content, tags }`，把日记原文追加写入 `data/diary_log.md`（纯文本备份，不覆盖）
- 写入令牌：设置环境变量 `WRITE_TOKEN` 后，写操作（`PUT`/`DELETE /api/graph`、`POST /api/save-diary-txt`）需带 `x-write-token` 头；页面可用 `?token=xxx` 一次写入浏览器
- `GET /health` 健康检查
- 访问门禁：设置 `SITE_PASS` 后，以上所有接口（含 `/health`）都需要 Basic Auth 凭证
- 单实例部署：不要多副本同时写同一个数据目录
